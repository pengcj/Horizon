## [Command injection vulnerability found in GTK-based PDF readers](https://lwn.net/Articles/1073944/) ⭐️ 8.0/10

Michael Catanzaro disclosed a command-injection vulnerability in GTK-based PDF readers Evince, Atril, and Xreader, where malicious polyglot PDF/ELF files can execute arbitrary code when users click embedded links. This vulnerability affects multiple widely-used GTK-based PDF readers and introduces a novel attack vector using polyglot files, posing significant real-world security risks for Linux desktop users. The exploit works by abusing the `--gtk-module` command line flag to load the malicious PDF as a GTK module, enabling arbitrary code execution through its library constructor, but this vector is mitigated in GTK 4, making the Papers PDF reader less vulnerable.

rss · LWN.net · May 21, 21:05

**Background**: A polyglot file is a single file that is valid in multiple formats, in this case both as a PDF and an ELF (Executable and Linkable Format) binary, which allows it to bypass simple file type checks. The `--gtk-module` option is a GTK command line flag used to load additional modules, and in this vulnerability, it is exploited to load the malicious file as a module. Arbitrary code execution refers to an attacker's ability to run any commands or code on a target system, typically leading to full system compromise.

After a five-year ground-up redesign, the new Freenet project is operational with a global, decentralized key-value store where keys are WebAssembly contracts, enabling applications like the River group chat and Delta CMS. The architecture introduces a unique state merging solution that uses commutative operations for rapid consistency across the peer-to-peer network. This represents a significant evolution for the historic Freenet project, potentially offering a robust platform for decentralized applications that operate like normal web apps but without central servers. Its success could demonstrate a viable model for achieving real-time consistency in distributed systems, addressing a core challenge in the decentralized web space. The platform currently supports desktop operating systems with installers, but mobile support, especially for iOS due to WebAssembly restrictions, is a noted blocker. Applications are downloaded from the network itself and run in a browser, connecting locally to a Freenet peer via websocket, though this design places the onus of defining merge logic on developers.

hackernews · sanity · May 21, 14:34 · [Discussion](https://news.ycombinator.com/item?id=48223362)

**Background**: Freenet, originally conceived in the early 2000s as a peer-to-peer platform for censorship-resistant communication, has been renamed Hyphanet, with this new version representing a complete rewrite. The new architecture uses a decentralized key-value store, a concept where data is stored and retrieved across a network without a central authority, combined with WebAssembly contracts—a portable binary code format—for defining application logic and data validity rules. The project's state merging approach, which requires commutative operations, is conceptually related to Conflict-free Replicated Data Types (CRDTs) used in distributed systems to allow concurrent updates without coordination.
