At the 2026 Linux Storage, Filesystem, Memory Management, and BPF Summit, Joshua Hahn presented a session highlighting that the Linux cgroup memory controller is not designed for modern tiered-memory systems and is seeking ways to improve it. This is significant because modern tiered-memory architectures are becoming more common, and the current controller's limitations could lead to inefficient resource allocation, poor performance isolation, and suboptimal memory placement in these systems. The core problem is that the existing memory controller, designed for homogeneous DRAM, lacks mechanisms to account for and manage memory across different performance tiers (e.g., fast DRAM vs. slower persistent memory) within a single cgroup.

rss · LWN.net · May 25, 15:03

**Background**: Linux control groups (cgroups) are a kernel feature for partitioning resources like CPU, memory, and I/O among processes. The memory controller specifically tracks and limits memory usage per group. A tiered-memory system, often involving CPU-less NUMA nodes with different types of memory, uses a hierarchy of storage media (like fast DRAM and slower persistent memory) to balance cost and performance.
