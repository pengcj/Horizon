## [IIS server legacy 8.3 filename vulnerability reexamined for security research.](https://mll.sh/humiliating-iis-servers-for-fun-and-jail-time/) ⭐️ 7.0/10

The article re-examines a legacy vulnerability in IIS servers related to the 8.3 filename convention inherited from DOS, which can expose internal file and folder names through the tilde (~) character in HTTP requests. This vulnerability is significant because it persists on modern Windows systems and, if exploited, can allow attackers to enumerate sensitive files on the server, potentially leading to further compromise. A key detail is that 8.3 filename generation is enabled by default on the Windows C: drive (where IIS's default web root `C:\Inetpub` resides) but disabled by default on other drives in Windows 10/11, and the vulnerability can be mitigated by disabling 8.3 filenames via a registry key.

hackernews · denysvitali · Jun 16, 22:53 · [Discussion](https://news.ycombinator.com/item?id=48563394)

**Background**: The 8.3 filename convention is a legacy system from DOS and early Windows that limits filenames to eight characters plus a three-character extension, creating a 'short name' version of longer filenames for compatibility. In IIS, this creates a vulnerability where the tilde character (~) followed by a number can be used to guess the short names of files and folders, a technique known as IIS tilde enumeration. This allows attackers to discover files that are not directly linked or intended to be public.
