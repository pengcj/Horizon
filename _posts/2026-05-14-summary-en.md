## [Critical 'Copy.Fail' Vulnerability Threatens All Major Linux Distributions](https://www.schneier.com/blog/archives/2026/05/copy-fail-linux-vulnerability.html) ⭐️ 9.0/10

Security researcher Theori has publicly disclosed CVE-2026-31431, a critical local privilege escalation vulnerability in the Linux kernel's crypto API (AF_ALG sockets) and splice() system call. The exploit allows an attacker to write four bytes at a time into the page cache of any readable file, such as a setuid binary, without altering the file on disk, effectively granting root privileges. This vulnerability is considered the worst Linux kernel flaw in years due to its simplicity, reliability, and broad impact across nearly all major distributions including Ubuntu, RHEL, and Debian. It enables reliable local root privilege escalation from an unprivileged user, posing a severe threat to servers, cloud environments, and multi-user systems. The vulnerability stems from a logic flaw in the algif_aead module introduced via an optimization in 2017, with a CVSS score of 7.8. Crucially, the exploit modifies only the in-memory page cache, so traditional file integrity monitoring tools like AIDE and Tripwire, which check disk contents, cannot detect the malicious alteration.

rss · Schneier on Security · May 12, 11:06

**Background**: The Linux kernel's AF_ALG socket interface provides a way for userspace programs to request cryptographic operations like encryption and hashing directly from the kernel. The splice() system call is used for efficient data transfer between file descriptors and pipes, often used to move data without copying it to userspace memory. A setuid binary is an executable file that runs with the permissions of the file's owner (often root), making it a common target for privilege escalation attacks.
